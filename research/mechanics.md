# Mechanics from supplied Stormworks resources

This pass owns only `wiki/data/mechanics.json`, `wiki/scripts/extract_mechanics.py` and this report. It reads shipped configuration, selected component descriptions and mission Lua. It does not attach to the shared REA native session, execute the game, alter original data or publish original game files.

The extractor produces 27 articles, 339 findings and 483 constant records from 71 source files. The expansion adds 11 articles, 198 findings, five selected component constants and 36 source files. All findings have a source path, full original-file SHA-256 and inclusive one-based line range. IDs beginning `resource:` identify local file evidence, not native REA session evidence. The original 16 articles and existing constant records retain their extraction behavior and schema.

## Reproduction

Run from the project root:

```bash
python wiki/scripts/extract_mechanics.py
python wiki/scripts/extract_mechanics.py --check
```

The script also works from another current directory. It uses the Python standard library and locates inputs relative to its own location. Output ordering is deterministic, and there are no timestamps or machine-specific absolute paths in the JSON. `--check` compares generated bytes without writing. Source digests cover original bytes, including CRLF, while line numbers count logical source lines.

The SDK constants document is parsed as XML. Selected component tags use a narrow attribute scanner because shipped definitions contain numeric attribute names such as `00` in rotation matrices, which a strict XML parser rejects. The scanner reads definition, logic-node and tooltip opening tags only. It neither repairs nor writes the source files. Realtime values retain their declared scalar/vector type and original value text. An unsupported nonempty realtime line fails extraction instead of disappearing silently.

New component articles can explicitly include ports with empty descriptions. Their findings say they are port labels only, with no inferred units, ranges or numeric node-type meaning. Selected short tooltips are separate findings so component roles and documented winch lengths retain their own source references. Both options are disabled by default to preserve existing extraction behavior.

## Evidence boundaries

- `observed` means a value or description was observed in the supplied file. It never means gameplay was observed.
- `sdk-documented-default` records come from SDK comments. `sdk-configuration` records come from the SDK XML element. They remain separate even when their values match.
- `realtime-configuration` is the value actually present in the supplied configuration file. It does not prove the binary loads that file, uses that setting in a particular mode or retains it after an override.
- `component-configuration` selects relevant fields on appropriate block types. Common serialized fields on unrelated blocks do not establish those mechanics.
- `component-interface-description` records developer-authored port descriptions and tooltips. These document intended interfaces rather than measured implementation behavior.
- `static-addon-lua` records describe the shipped script, conditional on enabling that addon and on server API semantics. Source expressions are retained where arithmetic matters.

Unknowns are explicit article limitations. No invented physics or efficiency equations were added. Every current finding is `observed`; possible interpretations that would need runtime or native evidence remain in limitations rather than being presented as findings.

## Coverage and findings

Physics has four articles. World gravity, damping and friction use SDK descriptions. Aerodynamics separates pressure and suction terms, lift and speed thresholds. Buoyancy and water drag separate wave, damping and mass parameters. Wheels and suspension expose internal grip, stiffness, damping and drive torque factors.

One cross-file disagreement deserves native follow-up. `sdk/data/game_constants.xml:67` assigns `buoyancy_mass_multiplier="10.0"`, while `rom/data/realtime_values/general_debug.txt:37` contains `f32 buoyancy_mass_multiplier 12`. The output preserves both hashes and ranges in `summary.sdkRealtimeDifferences`. File comparison establishes the discrepancy, not runtime precedence. This was the only differing value among names shared by SDK XML attributes and extracted realtime entries.

Engines have two articles. The small diesel engine documents throttle 0 to 1, electrical starting, separate fuel/air/exhaust ports and cold/hot coolant paths. Small and large `engine_max_force` fields are 20000 and 200000; these are internal fields rather than measured torque or power. Modular cylinder descriptions document adjacent-cylinder manifold sharing and composite channels 1 for air volume, 2 for fuel volume and 3 for temperature. Starter and alternator tooltips describe drive-belt attachment and energy transfer.

Electricity has one article. Battery charge capacities are 1600, 12800 and 256000, and their data output range is 0 to 1. Generator port descriptions document mechanical input and electrical generation output. Generator `electric_magnitude` values and realtime consumption scaling are exposed without converting them to watts or efficiency.

Fluids have one article. Tank outputs document litres and atmospheres; pump flow outputs document L/s. Selected small/large pump `pump_pressure` fields are 10 and 100 with units left unknown. Realtime gas and liquid base damping differ, 0.99 versus 0.9999, while their flow damping settings both read 0.0005.

Sensors have two articles. Linear speed, angular speed and altitude descriptions state m/s, rotations per second and metres above sea level. Selected radar inputs use turns, and the short range radar definition has `radar_range=5000`; target detection at that distance is not established. SDK noise comments distinguish position discrepancies from radar distance discrepancy, but do not give a probability distribution or prove active error bounds.

Control has one article. The PID Active input explicitly resets stored values when inactive. Port and tooltip descriptions establish setpoint, process variable, output and configurable control terms. Boolean capacitor behavior is recorded separately from electrical storage.

Economy has four articles. Fluid gantry branches use fixed displayed buy/sell prices for diesel at 2/3, jet fuel at 4/6 and oil at 0.5/1 per litre. These branches use their explicit price expressions rather than the resource table's `base` fields. Settlement uses signed tank deltas and rounding, with loaded-vehicle and minimum-transaction checks. Base resource storage uses named inlet/outlet tanks and tile inventory bookkeeping.

Oil survey data starts at 25000, and later quoted costs use `math.random(25000, 80000)` through named bounds. The purchase guard uses currency strictly greater than cost, so exact balance fails that source-level check. Initial purchased deposits use server-returned entry indices at most 5, with no geographic ordering assumed.

Cargo has explicit distance and rarity reward expressions, destination transform checks and separate loaded/unloaded expiration thresholds. Its timer accumulates the callback's `delta_worldtime`. The article preserves those expressions rather than inventing a global tick rate or treating the lifetime calculation as measured wall-clock time.

Environment has one article. It inventories sunrise/sunset lighting markers and separates tornado/whirlpool force terms. Lighting markers do not establish actual astronomical sunrise, mission timing or hazard damage.

## Expanded component coverage

All eleven additions are partially answered at the configuration and documented-interface level. None establishes native execution. Each article contains full source hashes and line references for its findings; `summary.sourceManifest` lists the full-file identities.

- `jet-engines` covers electrical compressor startup, jet fuel and throttle, pressure-dependent combustion without an invented ignition threshold, turbine telemetry and mechanical connections, afterburner fuel tradeoffs and thrust-spoiler endpoints. The medium turbine has an RPS-labelled port described as torque; the article preserves that ambiguity.
- `steam-heat-cycle` covers one-coal firebox ignition, air/exhaust/coolant interfaces, boiler heat supply and evaporation control, and condenser cooling. Boiler and condenser ports with empty descriptions remain labelled interfaces rather than inferred thermal measurements.
- `steam-mechanical-output` covers turbine torque documentation and piston extension/retraction through outer/inner couplings. Piston-position-based pressure alternation is developer tooltip guidance, not a derived valve timing equation.
- `nuclear-reactor-components` covers fuel rod insertion, uranium-ingot fueling from workbench inventory, adjacent-rod reaction reduction and labelled insertion/release/temperature interfaces. No reaction kinetics, insertion range or safety threshold is established.
- `transmission-gears-clutches` covers switching between two configured ratios, the selected gearbox tooltip's torque-difference limit of 4000 with units unknown, standard clutch engagement 0 to 1 and modular clutch attachment to the crankshaft. No ratio orientation, loss or slip equation is inferred.
- `marine-propellers` covers underwater-only operation, pitch input -1 to 1 and selected `force_emitter_max_force` fields 20000 and 80000. These are internal fields rather than thrust in newtons.
- `air-propellers-rotors` covers aircraft collective, large-rotor pitch/roll/collective, tail-rotor yaw and the large rotor's documented underwater reduction. Control ranges do not establish blade angles or a torque-to-thrust equation.
- `weapons-loading-fuses` covers electric autocannon feed, single-caliber drums, selected drum capacity 100, feeder direction, cannon breech/loading state and optional fuse time explicitly in seconds for high-explosive and fragmentation ammo. Selected barrel-length fields are recorded without interpreting projectile velocity, penetration or damage.
- `composite-cable-interfaces` covers the cable anchor's single-link constraint and separate composite, on/off, video and audio send/receive descriptions. Composite transport is partially documented. Microcontroller execution remains unresolved because the inspected `microprocessor.xml` tooltip descriptions are empty. No channel count, channel packing or Lua scheduler behavior is claimed.
- `winches-hose-coils` covers electrical operation, up/down controls, length in metres, hose-coil ports and the selected short tooltips' 20m/100m variant descriptions. These lengths are not runtime travel measurements.
- `connectors-hardpoints` covers magnetic attachment requiring both magnets enabled, proximity-based electric/fluid/torque attachment, documented resource/data transfer, attachment telemetry, hardpoint alignment and release versus launch. Ordnance-type numeric mappings remain unknown.

## Gaps for the parent investigation

- Runtime configuration loading and precedence, especially the buoyancy multiplier conflict. No effective native values are established by this pass.
- Gravity integration, solver timesteps, collision/contact equations, drag and lift equations, displacement and compartment buoyancy.
- Diesel and modular-engine torque curves, fuel consumption, optimal air/fuel mixture, thermal behavior, efficiency and overheating thresholds.
- Electrical capacity units, voltage, consumption, generator conversion, storage losses and SI power or energy conversion.
- Fluid network solving, pressure-flow curves, compression, transfer limits, mixture semantics and thermal effects.
- Sensor noise distribution, update cadence, detection/occlusion rules and other radar variants.
- PID discrete equation, timestep, anti-windup, output limits and derivative filtering.
- Runtime verification of addon activation, server API behavior and economy transactions. Mission Lua rules do not establish universal mechanics for every world or addon.
- Jet ignition thresholds, thrust/fuel/temperature equations, steam phase conversion and heat transfer, turbine/piston efficiency, and nuclear reaction, radiation and meltdown behavior require native or runtime evidence.
- Gearbox ratio orientation and losses, clutch slip, propeller/rotor force curves and winch tension, breakage and reel speed remain unknown.
- Weapon loading and fuse interfaces are documented, but projectile trajectory, drag, penetration, damage, blast radius and detonation implementation remain unresolved.
- Composite channel layout, microcontroller limits and scheduling, connector transfer capacity/latency and attachment distance/force limits remain unresolved. The inspected component definitions do not establish these behaviors.
- Other shipped addons and unselected component variants remain outside this focused pass. No negative claim about their mechanics follows from that boundary.

## Validation

Extraction and `--check` passed, including `--check` launched from `/tmp`. A separate validation walk checked all 824 source-reference objects for matching SHA-256 and valid inclusive line bounds, and all 71 manifest entries for hashes and logical line counts. It also checked evidence ID construction, unique article IDs, exact article/finding fields, non-null finding values, observed status, allowed evidence types and the expected buoyancy discrepancy. Two consecutive in-process builds matched the output, confirming reset and deterministic generation. The script passed Python AST parsing. No game execution or shared native-session operation was used.
