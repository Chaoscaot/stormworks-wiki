182:Slamming is a separate vector added only for a partially submerged surface, with additional orientation, velocity and position gates. Let q be the sampled vector passed as argument 6, a=-dot(q,normal), and b=-dot(q,v). For the active branch, a>0, b>0, and `q.y*(argument5_y-lever_arm.y) < b`:
185:F_slamming = q * a * pow(clamp(b,0,5)/5, 2)
186:             * m * (2*A / context_scalar_0x98) * slamming_force_multiplier
189:The multiplier read at `0x14048da7f`, bytes `f3 0f 10 80 e4 00 00 00`, uses default 100. The meaning of `context_scalar_0x98` and q's exact normalization are still open. Inference: q is the sampled water-surface normal. This is the decoded native algebra, not a complete wave-impact model.
191:The combined normal, viscous and slamming vector is capped in magnitude. `0x14048df3f`, bytes `f3 0f 59 bb 90 00 00 00`, multiplies speed by body mass; `0x14048df47` multiplies by 0.5; `0x14048df4c`, bytes `f3 0f 5e 3d 0c 28 72 00`, divides by 60. If the combined magnitude exceeds `s*m*0.5/60`, it is scaled down proportionally. This unusual scale is another reason not to label the input coefficients as standard SI drag coefficients.
193:The realtime switches `apply_drag`, `apply_viscous_resistance` and `apply_slamming_force` are absent in both string encodings. The recovered callback gates its terms by speed and geometry, and reads its constants from the native singleton/context. No realtime switch read was found. Therefore the file's enabled switches do not establish release runtime authority.
197:`calculate_air_density` is absent as ASCII and UTF-16LE. 199:This rules out interpreting `calculate_air_density=0` as a demonstrated global vacuum, zero-density switch, or proof that altitude effects are disabled. The separate control-surface path and its altitude pressure ratio were already decoded in `investigation/control-surfaces.md`; no global claim should override that evidence.
