59-## Endpoint order and latency limits
60-
61-The normal scene dispatcher first evaluates the selected components of all selected vehicles. In its later vehicle traversal it calls `0x1404baf80` at `0x140549a5b`, then flushes that vehicle's outputs at `0x140549ad2`. `0x1404baf80` calls `0x1404995b0` at `0x1404bb2b3`; that routine invokes each component's +0x360 method at `0x1404996a7`. Rope-hook +0x360 is `0x1403b6840`.
62-
63:Consequently cable copying takes place after the main component-evaluation pass, inside a traversal where each vehicle's component transport precedes that vehicle's output flush. It is not one global cable-copy pass followed by one global output-flush pass. A write into another vehicle's receiving output can land before or after that vehicle's output flush. Inference: cross-vehicle ordering can add a cache-publication boundary. A fixed tick count for all endpoint orders, cable chains and pulley arrangements is not established.
64-
65:The one-update inference for an ordinary physical composite wire does not automatically extend to an entire route through producer wire, cable anchors and consumer wire. Additional unresolved conditions include construction of +0xa98/+0xaa0, vehicle ordering, alternate +0x360 dispatch paths, state guards, sleeping vehicles and reduced-rate microprocessors. A wall-clock latency measurement was not performed.

67-## Remaining questions and exact exclusions
68-
69-- Maximum total external ports remains open. The recovered controls bound each physical axis to 1..6, and placement validity bounds coordinates and rejects certain same-position kinds. The total accepted kind set and all creation/serialization caps were not exhaustively traced. The editor scan retained as `asm/editor-search-window.asm` contains allocation-capacity comparisons to 0x20, including `0x14063cc76`, in container shrinking code. Those are not evidence of a 32-port cap. Neither the 32-channel payload nor the 6x6 area supplies the missing total count. A 36-port total is also unproved because the validity routine can accept different kinds at the same position.
70:- Cross-vehicle and pulley-chain latency remains open as described above. Recursive evaluation in the cached getter, pointer aliasing for composite copies and a universally fixed one-tick delay are ruled out as explanations of the recovered path. This does not rule out a one-tick result for a particular tested wiring arrangement.
71-- Ultimate video resource ownership remains open. Fixed descriptor assignment and the absence of dynamic pixel allocation/copy or reference-count arithmetic in `0x1402e9ab0` are established. Producer allocation, opaque field interpretation, renderer consumption and destruction were not traced.
72-- Lua scheduling remains open. The input API guards and getters were traced only to establish channel access. Deriving onTick/onDraw cadence, inactive behavior or execution budgets from these getters, channel counts or XML type IDs is ruled out. Executable help at `0x140af1270` says onDraw may run for multiple monitors and input/output functions have no effect there; that description is not a complete scheduler trace.
73-- Composite network packet/save format remains open. The 0x84-byte layout is an in-memory value and copy contract. No network serializer was traced.
