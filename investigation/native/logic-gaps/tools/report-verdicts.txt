5:## 1. Modulo, Exponent and Trigonometry helpers
7:Verdict: answered for the requested mathematical edge cases and gate angle units. Exact last-bit transcendental results for every input and every CPU dispatch branch are outside this report.
45:Wiki-ready replacement: "Modulo uses CRT fmodf with truncation toward zero and the dividend's sign, after a small-divisor guard. Exponent uses CRT powf after a guard that rejects negative bases with exponents below one and zero with negative exponents. Invalid or infinite sanitized results become zero. The Trigonometry block exposes turns using CRT sine, cosine, tangent and their inverses."
47:## 2. Function-block expression language
49:Verdict: answered for the numeric grammar, operator precedence, function inventory, constants, numeric precision, parser failure and small-divisor behavior. This is the numeric language, not the separate Boolean-expression language.
85:Wiki-ready replacement: "Function blocks use a binary32 numeric expression evaluator with variables x,y,z,w,a,b,c,d, constants pi and pi2, parentheses, unary signs, right-associative power, multiplication/division/remainder and addition/subtraction. The supported functions include trigonometry in radians, rounding, vector lengths, min/max, lerp and clamp. Division by zero returns zero, parse failures invalidate the expression, and evaluation has a thirty-two-value operand stack."
95:## 3. Power Add and Power Meter
97:Verdict: partly. No transmission-network formula for either legacy definition was recovered. In particular, this investigation does not substantiate a sum-of-power, weighted-RPS, torque-times-RPS or efficiency formula for either block.
111:Wiki-ready replacement: "Power Add and Power Meter select no-calculation branches in the logic tick. Their shipped definitions each expose a mechanical output, but no transmission formula has been recovered, so their names and old tooltips do not establish addition or measurement behavior."
113:## 4. Train Junction Controller
115:Verdict: partly. Junction selection, edge-triggered route changes and direct-write conflict behavior are recovered. A user-facing left/right label for every track orientation and a stable global winner among vehicles remain unproved.
139:Wiki-ready replacement: "A Train Junction Controller binds once to the nearest eligible junction strictly within thirty world-distance units and toggles its route bit on rising input edges. Train routing reads that bit to choose a branch. Multiple controllers write the same junction directly, so the last actual write wins; a stable cross-vehicle priority order has not been established."
141:## 5. Microprocessor ports, graphs, links and IDs
143:Verdict: partly. Binary external-port and nested-group readers have a recovered hard per-list read range. Editor creation, XML import, ID allocation and graph execution still do not establish one unconditional maximum across every path.
194:Wiki-ready replacement: "Microprocessor limits depend on the path. The binary external-port and nested-group readers accept nonzero list counts only through 32,768, while ordinary component collections use wider counts. Editor and XML creation use dynamic collections and separate DWORD ID counters. The 144-port figure is a derived placement bound for supported port types on the editor's largest footprint, not an unconditional storage or execution limit."
